# ADR 0002. Смена источника данных на TheCocktailDB

## Статус

Принято.

## Контекст

Приложение использовало **Absolut Drinks Database (ADDB)** (`addb.absolutdrinks.com`).
Сервис прекратил работу, поэтому поиск коктейлей перестал возвращать данные. Нужен
бесплатный и стабильный источник рецептов коктейлей.

## Решение

Перейти на **TheCocktailDB** (<https://www.thecocktaildb.com/documentation>):

- Base URL `https://www.thecocktaildb.com/api/json/v1/{apiKey}/`; в разработке используется
  бесплатный тестовый ключ `1` (переопределяется через `local.properties` → `BuildConfig`);
- эндпоинты: `search.php?s=` (по имени), `filter.php?i=/g=/c=/a=` (ингредиент/бокал/категория/
  алкогольность), `lookup.php?i=` (полная запись по id);
- модели — `CocktailDbResponse`/`CocktailDbDrink` (`strIngredient1..15`/`strMeasure1..15`),
  мапятся в `DrinkEntity` через `CocktailDbDrinkMapper`;
- UI фильтров **сохранён**; неподдерживаемые параметры (`taste`, `carbonated`, `color`, `skill`)
  остаются в `SearchConditions` и пока игнорируются;
- детали удалённого напитка загружаются по id (`lookup.php`), поэтому маршрут изменён с
  `remote_drink?entity=<json>` на `remote_drink/{drinkId}`;
- ингредиенты приходят в самой записи коктейля, эндпоинт «шаги приготовления» и пагинация
  (`start`/`pageSize`) удалены как отсутствующие в источнике.

## Последствия

- Поиск снова работает: имя/ингредиент/бокал/алкогольность.
- TheCocktailDB поддерживает только **один** фильтр за запрос — остальные параметры UI не
  применяются (задокументировано в [NETWORKING.md](../NETWORKING.md)).
- Результаты `filter.php` приходят без ингредиентов — детали догружаются через `lookup.php`.
- Нет рейтинга/вкуса/цвета/крепости/газированности и пагинации.
- Игнорируемые параметры зарезервированы под будущую пост-обработку результатов
  (например, AI-анализ).
